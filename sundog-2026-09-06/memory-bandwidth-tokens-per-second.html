Hardware tradeoffs

Buy the Memory You Need, Then Ask How Fast It Runs

Separate model capacity from decode speed. Read GPU bandwidth specifications, idealized calculations and multi-GPU split assumptions before choosing an upgrade.

By Sundog

6 September 2026

The next GPU is tempting. Your current card fits the model, yet a long reply still arrives one slow piece at a time. Before buying the replacement, separate two purchases: room for the session, and speed once the session fits.

Memory bandwidth is useful for screening the second purchase. It gives a rough limit for a weight-streaming workload. It cannot establish the speed of a quantized kernel, the cost of a long attention cache, or the performance of a particular multi-GPU split.[1][2] I did not test these systems with a decode benchmark.

Buy capacity for the workload you intend to keep

First confirm that weights, context and runtime fit; then compare bandwidth and matched measurements for the configurations that remain. More memory can admit the model you want while delivering slower single-session replies. A faster card that forces you back to a smaller model makes the opposite trade.

[OPINION] I would keep the current card until a repeatable local task shows which limit I am buying my way out of. The spec sheet is a filter for the benchmark request.

GPU generations make uneven bandwidth gains

NVIDIA's whitepapers give a useful three-generation comparison. Their peak FP32 rates are based on GPU Boost Clock; the memory bandwidth figures are specifications, not a llama.cpp measurement.[3][4][5]

The bandwidth increase from 3090 to 4090 is about 8%. From 4090 to 5090 it is about 78%, calculated from those rows. That alone defeats the idea that successive generations buy a fixed improvement in the feed rate. It does not establish either card's speedup on your model.

Keep bandwidth and bus width separate. The 78% figure describes bytes per second. A 384-bit interface becoming 512-bit is a 33% width increase; memory data rate contributes the rest.[3] Calling both changes a wider bus hides the mechanism you were trying to inspect.

The last column also needs care. Peak FP32 divided by bandwidth gives the ridge of an FP32 reference roofline. A quantized inference kernel has its own operations, conversion work and effective throughput. Those three ratios cannot tell you where NVIDIA spent its transistors or certify a buying recommendation for Q4 decode.[1] The arithmetic is correct. The larger story sometimes attached to it is unsupported.

Read the exact card inside the generation

The 80-class sequence prints bandwidths of 760, 716.8 and 960 GB/sec alongside FP32 rates of 34.1, 48.7 and 56.3 TFLOPS. The 70-class sequence prints 448, 504 and 672 GB/sec alongside 20.3, 29.1 and 30.9 TFLOPS.[3] The FP32 reference ratios are 44.9 / 67.9 / 58.7 and 45.3 / 57.7 / 46.0 respectively. Again, those are calculated reference ratios rather than inference results.

The within-generation choice deserves its own look. An RTX 5070 Ti is specified at 896 GB/sec and 43.9 TFLOPS; an RTX 5070 at 672 GB/sec and 30.9 TFLOPS.[3] That is a third more specified bandwidth for the Ti. It makes the two cards different candidates even before you compare memory capacity. There is no need to turn the difference into an unmeasured tokens-per-second promise.

A bandwidth calculation is a deliberately small model

Assume a hypothetical dense weight artifact of exactly 5.00 GB, read once per output token, with perfect use of the specified bandwidth. Ignore cache traffic, computation, dequantization and scheduling. Under those assumptions, dividing bytes per second by bytes per token gives the idealized weight-streaming rate.[2]

rweights=BmemoryWread per token

For this illustrative 5.00 GB artifact: about 187 tok/s on a 3090, 202 on a 4090, and 358 on a 5090. Calculated screening values, never measured results.

Real kernels can leave bandwidth unused. Attention adds work and traffic. Offload introduces another memory path. An MoE model activates a subset of experts, so dividing by the entire stored file has different meaning. Qwen3-Coder-Next's model card distinguishes its active and total parameters. Speculative decoding can also change the relationship between a weight pass and emitted tokens. Treat the assumptions as part of the calculation, rather than printing its answer alone.

Runtime changes matter for the comparison. The thirteen merged llama.cpp changes listed below include backend-specific changes, model support and a version bump.[6] It does not imply thirteen CUDA decode improvements. Check that a change applies to your backend and model. The server's fit option adjusts unset parameters; inspect the effective context instead of assuming the requested session survived loading unchanged.[7]

Large-memory machines make the tradeoff visible

The bartowski Llama 3.3 70B Instruct Q4_K_M artifact checked for this comparison is 42,520,398,816 bytes.[8] An RTX 5090 has 32 GB of local memory.[3] Keeping that complete artifact on one 5090 is unavailable before cache enters the discussion. Offloading remains possible, with another performance question attached.

DGX Spark offers 128 GB of unified memory at a specified 273 GB/s.[9] Apple's M5 Max Mac Studio configurations list 460 GB/s or 614 GB/s, and the M5 Ultra lists 1.2 TB/s. Maximum unified-memory configurations reach 128 GB and 512 GB respectively.[10] As of 6 September 2026, these Mac Studio models have been announced for availability beginning 22 September; the 512 GB option is scheduled for late October.[11] Keep the announced machine in the planning comparison until shipping hardware can supply a benchmark.

Each rate assumes the entire dense artifact is read once per token at peak bandwidth. No cache, computation, transfer overhead, operating-system reservation or runtime buffer appears in that column. The memory column lists installed or maximum capacity. An actual allocation for this workload remains untested. Apple figures also depend on buying the specified configuration.

Four cards do not automatically give one token four buses

llama.cpp describes layer split as pipeline parallelism: different cards hold different layers and a token passes through them sequentially.[12] In a simplified batch-one pass across identical 3090s, the time spent reading each layer slice adds. Four quarter-files read in sequence cost one full file at one card's bandwidth. The table therefore uses one card's 936 GB/sec for the sequential pass.

Tensor parallelism can make several cards work on the same layer, at the cost of cross-card communication. Its result depends on the backend, model, kernels and actual interconnect topology.[12] NVIDIA's statement that three-way and four-way SLI are unsupported does not mean a four-card inference rig cannot contain NVLink-connected pairs. It does mean you should not assume a uniform all-four NVLink fabric from the presence of those connectors.[13]

vLLM recommends considering pipeline parallelism where a node lacks NVLink, with communication overhead as the reason.[14] That deployment guidance leaves the performance of your 3090 topology to measure. Ask for a run that names model, quantization, runtime build, split mode, context and concurrency before paying for a claimed multi-card speedup.

Ask the benchmark to answer the purchase

Keep power ratings out of an inference-efficiency comparison. Spark's 240 W supply, a Mac Studio's 480 W maximum continuous power specification, and the RTX 3090's 350 W graphics-power rating describe different boundaries.[9][10][13] They are no substitute for measured power over the same completed workload.

[OPINION] I would request two benchmark depths: the short exchange that currently feels fine and the long session that makes me want new hardware. Hold the model artifact and build constant. Record prompt processing, decode, effective context, peak memory and completed-task time separately. If the seller's evidence only covers the first depth, the expensive part of my question remains unanswered.

The bandwidth column tells you where to look. The matched run tells you whether the upgrade buys the afternoon back.
