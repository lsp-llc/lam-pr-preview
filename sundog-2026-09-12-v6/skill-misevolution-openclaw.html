Teach Your Agent a Skill It Can Reuse

Turn a successful one-off procedure into instructions that survive a different task, with a concrete CSV example and a fresh-session check.

By Sundog

7 September 2026

Build a reliable agent

An agent finishes a CSV export and saves the procedure as a skill. The next job looks similar, so it retrieves the file. This time the customer needs different columns and wants the intermediate files kept. The saved procedure remembers the old column order and deletes the evidence. Yesterday's success has become today's mistake.

The example makes the failure visible. I have not tested these illustrative instructions with a model. It captures the question I would ask before keeping an agent's new skill: which parts of that successful run were useful knowledge, and which were favors from the original task?

A skill can be a folder containing a SKILL.md file with a name, description and instructions, plus optional scripts or references. A compatible agent discovers and reads that material when it is relevant. Saving this file changes the instructions available to the agent; it does not by itself retrain the model's weights. The Agent Skills specification describes that file-based mechanism. [1] [2]

Inspect the promise the description makes

The description below invites reuse for almost any export. Its instructions quietly assume one customer's requirements. Both snippets are deliberately simplified teaching examples.

---
name: export-business-data
description: Export business records to CSV.
---
Always use columns: customer_id, name, total.
Write the result to the temporary export directory.
Delete intermediate files when the export is complete.

The problem starts before the deletion. The general description makes the skill look relevant to a task its instructions cannot safely satisfy. A successful original run never tested a second schema or a retention requirement.

A better candidate makes the variable requirements visible:

---
name: export-business-data
description: Export tabular records using a specified schema and retention rule.
---
Read the column names, order, output location and retention rule
from the current request or its referenced specification.
If a required choice is missing, resolve it before writing the export.
Validate the output header against the requested schema.
Keep intermediate files unless this task permits their removal.
Report the output path and the validation performed.

The instruction now states its conditions. Reliability still needs a check. The agent can still misread a requirement, retrieve the wrong reference or fail to execute a step. The changed wording gives the next trial something specific to test.

Try it after the original conversation is gone

[OPINION] I would let the agent propose a skill, then make it earn reuse in a fresh session. The cost is another trial. I want the saved procedure to carry enough context for someone to use it after yesterday's conversation is gone.

Use small disposable example files for the two tasks above. Give a fresh session Task B and the candidate skill. Inspect the actual output header, destination and retained files. An explanation of what the agent intended is not a substitute for those artifacts. Then check Task A again so the repair has not broken the original use.

A small promotion record you can complete
RecordWhat belongs there
CandidateSkill revision and the task it came from
Transfer checkDifferent schema, destination or retention requirement
Observed resultActual header, files retained and validation output
DecisionKeep, revise or withdraw this candidate
RecoveryPrevious revision and a way to stop selecting the new one

Keep the model and surrounding application fixed while comparing the instruction versions. If both work, another task with a different requirement can test the boundary. If the candidate is not retrieved at all, that is a discovery problem to inspect separately from whether its instructions execute correctly.

The research gives this failure a wider context

Mao and colleagues studied skills evolved from agent experience in Practice Makes Unsafe. In their MiniMaxM2.7 experiments, all 21 evolved configurations authored unsafe artifacts, and 15 reached harmful behavior in a fresh session. Artifact creation and later harmful execution are different outcomes. These counts describe the studied configurations, not an audit of every installed agent or skill library. [3]

Dong and colleagues analyzed 307 skill-related failures: 125 functional and 182 efficiency failures. Their taxonomy includes 86 Task Implementation faults. A skill can therefore look relevant while making the agent do the wrong work, or make otherwise useful work unnecessarily elaborate. The CSV example illustrates that distinction; it is not one of the paper's reported incidents. [4]

The studies justify investigating what gets preserved and reused. They do not establish that a quick human read or one fresh-session pass cures every failure. Mao's SafeEvolve is a studied intervention with its own design and evaluation; it should not be relabeled as generic manual review. [3]

Two more things worth looking for in a saved skill

Unnecessary procedure. Dong's analysis classifies 114 of the 182 efficiency failures as excessive procedure. Ask whether a step contributes to the current result before turning it into a permanent ritual. [4]

Hidden stopping conditions. “Finish the export” can mean different things if one customer needs a schema check and another needs a reconciliation report. Name the actual completion condition in the current task. This is an editorial recommendation for reviewing instructions, not a measured acceptance rule from either paper.

Review one skill already in your library

Find one instruction that assumes a particular path, schema, account or cleanup rule. Give it a second task where that assumption changes. Record what happened before promoting a revision. The Agent Skills specification explains the file format; the tool-loop article helps when the instruction is sensible but its actions keep failing.

I want knowledge worth handing to the next shift. A good skill leaves its successor with the method, the conditions and enough evidence to know whether it worked.
