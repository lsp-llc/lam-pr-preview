Your Agent Can Lose Track of the World Before It Breaks a Rule

Separate remembering the current state, predicting an action’s effect, and choosing the action. A legal move can still follow a false picture of the world.

By Sundog

29 September 2026 · 7 min read · Agent engineering

An agent moves a parcel into storage, walks back to the loading bay, and then searches the loading bay for that same parcel. Every movement was allowed. The job still stalls because the agent’s account of the world never caught up with its own action.

That is a different problem from choosing an illegal move or forgetting the user’s goal. An assistant working through tools must keep track of what is true now. A long transcript may contain every relevant event without giving the next decision a reliable picture of the current state.

Recent research separates state tracking from action success, and another study asks whether access to a simulator actually helps agents plan. Read together, they give local builders a useful diagnostic: inspect the state the agent is acting from before adding another planning tool. [1] [2]

Three things that “world model” can mean

The phrase often covers different components. A state record describes current facts: where the parcel is, which door is open, what the robot carries. A transition model predicts how those facts change after an action. A simulator tool lets the agent try a hypothetical action and inspect a predicted result.

They need not be the same system. Your program can maintain an exact state record, use deterministic rules for transitions, and offer a preview tool. Or an agent can write its own notes while trying to infer those rules. A research result about one component does not establish the reliability of the others.

A theorem about agents implicitly representing transition dynamics is another use of “world model.” It does not tell us whether a particular chat agent correctly updated its written inventory. I am using the narrower, observable sense here: the facts supplied to the next decision. [3]

A legal action can follow a false belief

Consider this original toy world. A robot starts in Bay A holding a parcel. It can move between Bay A and Store B, put a held parcel down, or pick up a parcel in its current room. The goal is to leave the parcel in Store B and return to Bay A empty-handed.

EventTrue state after the eventPossible stale note
StartRobot in A; parcel carriedRobot in A; parcel carried
Move to BRobot in B; parcel carriedRobot in B; parcel carried
Put parcel downRobot in B; parcel in B; hands emptyRobot in B; parcel in A; hands empty
Move to ARobot in A; parcel in B; hands empty; goal metRobot in A; parcel in A; hands empty

The return to Bay A is legal and completes the goal. Yet the stale note can prompt an unnecessary pickup attempt in A. The invalid action follows the state error after one intervening legal move. If you log only tool failures, you see the symptom late.

The transition can be written as st+1 = T(st, at): the next state comes from the previous state and the executed action. The agent acts using an estimate, ŝt. A valid action in ŝt can be invalid in the true st. This notation is useful because it forces us to identify which record the permission check and the planner actually consume.

In software work, the analogue is concrete: a file has already moved, a command has completed, an API result changed an identifier, or a prerequisite failed. A confident next step based on the previous state can waste effort even before it reaches a rejected tool call.

Research found state errors before action errors

World-Model Collapse as a Phase Transition instruments a controlled puzzle agent’s written state, action validity and final success. Its main harness has separate planning, updating and self-diagnosis calls. In paired collapse episodes, the reported median lead of state failure over the first invalid action is two steps. That is temporal ordering, not an intervention proving the state error caused the action error. [1]

The same study varies a state-complexity parameter and dependency density. In its main Claude Haiku 4.5 grid, the lowest state-complexity setting succeeds in all 100 episodes per dependency cell. At the next setting, success ranges from 100% to 20% as dependencies increase; the two highest settings have zero success. The boundary belongs to that puzzle and harness. It is not a number of entities every assistant can safely remember. [1]

The limitations matter here. The authors chose the confirmatory environment from pilots using a rule that required a substantial, readable performance drop. Other pilot environments did not produce the same pattern. Their complexity configurations also change several properties of the world, and the open-weight corner probe uses a 70B model rather than a small local assistant. This is evidence for inspecting state fidelity, not a universal capacity law for your 8B download. [1]

Choose a state metric that explains a decision

The paper compares the agent’s fact set with the true fact set using Jaccard similarity:

J(estimated, true) = |estimated ∩ true| / |estimated ∪ true|.

This penalizes missing and invented facts. In a simplified example, the true set has four facts. The agent retains three correctly and substitutes one wrong fact for the fourth. There are three shared facts and five in the union, so J = 3/5 = 0.6.

That score treats all facts equally. Missing a decorative room label can hurt the score without affecting the next move; getting “parcel carried” wrong can determine whether pickup is legal. I would therefore report both full-state fidelity and correctness of the facts needed by the chosen action. The second measurement is a proposed diagnostic addition, not a result from the paper.

Also record when the observation was taken. Compare a post-action note with the post-action truth, not the state from before the tool call. A timing mistake in the evaluator can manufacture an apparent state failure.

An accurate simulator is still a tool the agent must use well

Current Agents Fail to Leverage World Model as Tool for Foresight tests nine vision-language models with no simulator, optional access, or required simulation. For its agent tasks, the simulator clones the environment and is oracle-accurate. This is a strong prediction source; the agent still has to decide what to simulate, read the result and use it. [2]

For Qwen2.5-VL-7B, mean success across the four agent tasks is 0.20 without access, 0.20 with optional access, and 0.08 with forced use. Those are task averages, not one pooled success rate. Optional access produces mixed individual-task changes even where the average is unchanged. Other models also show that compulsory use can reduce success. [2]

The experiments use a limited interaction budget. Whether simulation consumes turns in precisely the same way as real actions is not fully resolved by the reported protocol, so budget overhead is a possible contributor to forced-mode losses. The findings do not show that accurate prediction is useless. They show that prediction access and successful planning are separate engineering achievements.

Give the planner a state it can audit

For a local tool agent, start with observable facts your program already knows: actual command status, resource identifiers, inventory, completed steps and outstanding prerequisites. Record observations separately from forecasts. A successful preview is not an executed action, and an intended file edit is not a confirmed file edit.

You can investigate the state bottleneck in a small deterministic world by comparing two conditions: the agent updates its own notes, or the program supplies the true current state at each step. Keep action permissions and the decision budget identical. Score goal completion, legal moves, state accuracy and action-relevant facts separately. This comparison is proposed; neither cited study establishes that supplying true state will fix your local model.

If it helps, you have evidence to improve the updater or the state interface. If it does not, the next investigation may concern transition knowledge, goal interpretation or action selection. Make that decision from traces, not from the smoothness of the agent’s narration.

[OPINION] Before giving an assistant another way to imagine the future, I want a readable account of the present. A concise state record with confirmed transitions gives me something to inspect. That is also a better place to repair a stalled job than asking the model to rethink a world it has already misplaced.
